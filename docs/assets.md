# Where a file goes

From the asset audit of 2026-11-11. One rule, then the exceptions.

**A picture a page shows goes in `src/assets/` and is imported by the page.** Astro resizes it, makes WebP/AVIF and
gives it a hashed name under `/_astro/`, which browsers keep for a year. A file in `src/assets/` that nothing imports
does not belong in this repo (see "When a file is no longer used").

## What `public/` is for

Files in `public/` ship exactly as they are, under the same name. Only these go there:

| Folder | What | Why it is not in `src/assets/` |
|---|---|---|
| `email/`, `updates/*.json`, `manuals/*.pdf`, `og/`, `og-default.*`, `favicon.*`, `robots.txt`, `CNAME` | Files loaded from outside the site: emails already sent, the plugins' update check, links in manuals and stores | The URL is a contract. **Never rename or move these.** |
| `audio/`, `drift/` (videos, posters, `band-vocal.bin`) | Sound and video | Astro's optimizer handles pictures only |
| `station-mixer/`, `gas-mixer/` | The mixers on the Radio Roulette and GAS pages | Generated by `tools/<name>/export_component.py`. Never edit by hand: change the bench and export again |
| `fonts/drift/` | Fonts a page skin loads by URL | The site's own fonts are in `src/styles/fonts/` and go through the pipeline |
| `plate/arm-mount-v3*.png`, `bg/` | Art a component's CSS loads by URL | Old; move to `src/assets/` when that component is next touched |
| `bench/` | Slider and drag tools that open the site in a frame | Dev server only: the build leaves the folder out (`benchdevonly` in `astro.config.mjs`) |

A picture in `public/` is WebP (or JPG for a photo). A PNG there is a master that was never converted.

## Two pages that are copied in whole

- `tools/_gas2-scene/` → `/gas2/` (`tools/gas2page/integration.mjs`). PNG masters stay beside the WebP the page loads;
  the build skips `.png`.
- `tools/_home-opening/` → `/garage-9f3c/` (`tools/garagepage/integration.mjs`).

## Versions on the URLs (`tools/assetver/`)

GitHub Pages stamps every file with the deploy time, so without help a returning visitor downloads everything outside
`/_astro/` again after each deploy. The last step of the build adds `?v=<hash of the file>` to the URLs of files in
`station-mixer/`, `gas-mixer/`, `gas2/`, `audio/`, `fonts/` and `drift/`, where the URL is written out in a page or in
those folders' own CSS and JS. A Cloudflare cache rule keeps a URL with `?v=` for a long time; a changed file gets a new
URL. A name a script builds at run time (the mixer stems, for one) gets no version and keeps the 10-minute cache.

Nothing to do when adding a file: the build does it. To let a new `public/` folder join, add it to `FOLDERS` in
`tools/assetver/integration.mjs` and to the Cloudflare rule.

## Not on the site

- `bench/` (repo root): bench pages, their settings and scratch art.
- `tasks/evidence/`: QA screenshots.
- Masters and retired art: the asset library, `revaudio-kit` (browse its `index.html`).

## When a file is no longer used

1. Search the code for its file name (`git grep -F <name>`), and for a `public/` file also the other RevAudio repos:
   its URL is public.
2. If the library copies it from this repo (`revaudio-kit/sources.json`), move the library's copy into that folder's
   `archive/` first. The library's sync deletes what the site deletes, except inside `archive/`.
3. Remove it here. Git history keeps it.
